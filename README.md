# Estratto Operazioni

Генератор PDF-выписок по открытым и закрытым сделкам. Это статический сайт: сервер и база данных не нужны.
Вся обработка (разбор сделок, сборка PDF, QR-код, логотип) идёт в браузере пользователя, данные клиентов никуда не отправляются.

## Что внутри

```
index.html        — сам сайт
fonts/            — шрифт Inter для PDF (обязательно рядом с index.html)
vendor/           — библиотеки: jsPDF (PDF), qrcode-generator (QR), pdf.js (предпросмотр)
vercel.json       — кэширование и запрет индексации поисковиками
```

## Деплой на Vercel

### Вариант 1 — через GitHub (удобно обновлять)
1. Создайте новый репозиторий на GitHub и загрузите в него содержимое этой папки (все файлы и папки `fonts`, `vendor`).
2. На vercel.com: **Add New → Project → Import** этот репозиторий.
3. Framework Preset: **Other**. Build Command — пусто. Output Directory — пусто (корень).
4. **Deploy**. Через минуту сайт будет доступен по адресу вида `имя-проекта.vercel.app`.

### Вариант 2 — из терминала
```bash
cd vercel-estratto
npx vercel          # первый раз: войти и ответить на вопросы (настройки по умолчанию)
npx vercel --prod   # выложить в продакшн
```

### Свой домен
Vercel → проект → **Settings → Domains** → добавить, например, `statements.вашсайт.com` и прописать DNS-запись, которую покажет Vercel.

## Важно

- Настройки (компания, адрес, сайт для QR, логотип) хранятся в браузере — у каждого компьютера/браузера свои.
- Сайт закрыт от поисковиков (`noindex`), но открыт любому, у кого есть ссылка. Сам по себе он ничего не хранит,
  но если нужна защита паролем — включите **Vercel → Settings → Deployment Protection** (на платных тарифах)
  или держите ссылку только у сотрудников.
- Формат вставки сделок: таблица прямо из CRM (каждая ячейка на своей строке) или «одна сделка — одна строка»:
  `ID  Инструмент  Buy/Sell  Капитал  Плечо  Открытие  Закрытие  P/L`.

## Выписка по торговому счёту

Раздел **Account Statements / Торговый счёт** работает независимо от выписки по сделкам.
Остатки и криптоактивы заполняются вручную. Историю пополнений и выводов можно вставить из CRM через режим «Автоматически / CRM».

- Укажите клиента, Account ID, дату выписки и валюту оценки. Публичный ID в выписке по счёту не используется.
- В полях названия, символа, кошелька и валюты открывается список с поиском на русском и английском. Для валют и криптоактивов используются отдельные справочники; выбор заполняет название и символ вместе. Поиск работает без сети, собственные активы можно вписывать вручную. При смене актива прежняя цена очищается, чтобы не использовать курс от другой позиции.
- Добавьте денежные остатки и криптоактивы: название, символ, кошелёк, количество и цену в валюте оценки.
- Числа форматируются при вводе: `1234567.89` → `1.234.567,89`. Точку и запятую можно использовать как десятичный разделитель. При выходе из поля суммы дополняются до двух знаков, цены — до четырёх; введённая большая точность не обрезается. Внутри сохраняются точные значения без разделителей тысяч.
- Стоимость каждой позиции — количество × цена, с округлением до четырёх знаков; общий баланс — сумма стоимостей позиций. Для расчётов используется точная десятичная арифметика.
- Операции вводятся отдельно: дата, тип, сумма со знаком, валюта, статус, описание и необязательный ID. Они не прибавляются повторно к остаткам; суммы разных валют не складываются.
- В PDF вместо Stocks Portfolio выводится **Movimenti del conto**. Если операции не введены, документ сообщает, что данные о них не предоставлены.
- Реквизиты компании, QR-сайт и логотип общие для обоих видов выписок. Полный редактор SVG-логотипа доступен прямо в каждом разделе: загрузка, выбор элементов, перекрашивание, сброс и удаление. Данные счёта сохраняются отдельно в браузере.
- Предпросмотр работает и для неполной формы без дополнительных пометок в PDF. При нажатии «Скачать PDF» неверные или обязательные незаполненные поля подсвечиваются красным с пояснением; фокус переходит к первой ошибке. После исправления файл скачивается. Ошибка предпросмотра не блокирует скачивание уже сформированного файла.

Локальный запуск: `python -m http.server 8000` из корня проекта.
Проверки расчётов, форматирования, валидации и импорта: `node --test tests/account-core.test.cjs tests/account-deposits.test.cjs`.

### Вставка истории CRM

1. В разделе счёта выберите **Автоматически / CRM** и укажите тип истории: пополнения или выводы. Направление не угадывается по одинаковым колонкам.
2. Вставьте скопированные строки с заголовками `ID`, `Dest currency`, `Dest amount`, `Order method`, `Order status`, `Trading users`, `Created`. Поддерживаются вертикальная копия с маркером `sd`, таблица с табуляциями и смешанные переносы из браузера; пустые Network, Payment Requisites и Last note не сдвигают данные.
3. После вставки клиент и операции заполняются автоматически, без кнопки добавления. Результат показывает распознанные записи и количество добавленных/обновлённых операций. В автоматическом режиме ручная форма операций скрыта; кнопка «Редактировать операции вручную» возвращает её. Для другого клиента имя нужно явно подтвердить; разные клиенты в одном вставленном отчёте не смешиваются. Ошибка новой вставки блокирует скачивание прежней истории до исправления или явного возврата в ручной режим.
4. Повторные ID пропускаются. Если у уже импортированной записи изменился только статус, он обновляется без удаления другой истории. Противоречащие даты, суммы или валюты требуют проверки. Замена всей истории доступна отдельным флажком и по умолчанию отключена.

В PDF используются итальянские названия: `Versamento`, `Prelievo`, `Bonifico bancario`, `Approvato`, `In attesa di approvazione`, `Non riuscito`, `Rifiutato`, `Annullato`. Ожидающие и неисполненные заявки сохраняются в истории, но не входят в сумму подтверждённых операций. Notes и платёжные реквизиты из источника не попадают в PDF или сохранённые операции. История не прибавляется повторно к остаткам. Номер счёта и портфели не выдумываются из истории.
